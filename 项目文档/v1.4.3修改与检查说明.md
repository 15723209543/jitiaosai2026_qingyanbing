# v1.4.3 方案B1修改与检查说明

日期：2026-10-16。起点13c65a9（用户提交v1.4.2），修改前已fetch，HEAD与origin/main一致。此版本不训练、不整批预测、不改变已有pth/config/CSV，不变更deepStudy或jitiaosai。

## 1. 七项建议的取舍

| 建议 | 结论与本次实施 |
|---|---|
| 修改学习率 | 采用：已训练卷积从5e-5降至1e-5，新分类头用1e-4；同结构续训也用这两组，无迁移时全网1e-4；调度按AUROC，两组分别记录 |
| 每期训练图片数量 | 区分每批和每轮：每批64不变，每轮抽样51396次不变，避免删数据或为降低loss减少样本；batch不是越大越准 |
| 修改模型层数 | 采用精简而非堆层：五层卷积不变，删除中间2048→2048全连接层 |
| 每层神经元数量 | 分类头4608→512→2；卷积32/64/128/256/512不变。参数降至3929410，FP32约15.72MB |
| 部分失活 | 需要且已有：保留卷积0.1、分类头0.5，不再盲目提高比例 |
| 梯度截断 | 增加全参数L2范数上限5、非有限值报错；仅稳定性保护，无证据证明之前存在梯度爆炸或此项必然提分 |
| 修改激活函数 | 暂不换：保留LeakyReLU(0.01)，保护已有特征和单一结构对照；更复杂函数不保证更优 |

只实施B1，输入64×64保持。96×96、更多池化、BatchNorm、残差网络和采样比例变化留给下一轮单独实验。当前已修改结构与分组学习率，不能把未来成绩变化精确归因于某一个因素。

## 2. AUROC唯一标准

完整验证集AUROC严格提高才覆盖正式模型；相等不更新，即使ACC/AUPRC提高。候选自身最高AUROC用于学习率和早停；最多12轮、连续5轮不改善停止；连续2轮不改善学习率减半，最低1e-6。没有旧模型时保存第一轮。

官网仍以AUROC为主、相同时AUPRC二次排序；本地唯一AUROC是用户本次明确要求，不冒称完全实现官网平局规则。

本次候选最佳也存入项目文档/训练记录/时间目录，不再只保留指标而丢掉对应参数；不保存每一轮，也不保存Adam完整续训状态。正式predict只用submission/model/best_model.pth。

## 3. 公开检索结果与依据

以“2026 计算机能力挑战赛 青光眼 方案”“glaucoma_first”“大数据挑战赛 青光眼 baseline”等关键词检索，并检查GitHub、CSDN、B站相关索引；本次可访问结果中，未找到能够核实代码、数据划分与本届成绩对应关系的高分方案。未把其他青光眼赛事或其他大数据赛的宣传成绩当成本赛证据，也未采购或复制他人比赛代码。

- [本届官方规程](https://www.ncccu.org.cn/index/Paper/case2.html)：AUROC主指标、AUPRC平局排序，初赛CSV，≤500MB、单张≤100ms，仅主办方数据。
- [PyTorch梯度范数截断](https://docs.pytorch.org/docs/2.10/generated/torch.nn.utils.clip_grad_norm_.html)：按所有参数梯度的总范数原地缩放，并可拒绝非有限梯度。
- [PyTorch自适应平均池化](https://docs.pytorch.org/docs/2.10/generated/torch.nn.AdaptiveAvgPool2d.html)：输出固定空间尺寸；本版保留原3×3汇总。

参数选择主要依据本地记录：今日第1轮AUROC0.919544，第11轮0.905103；按ACC却保留第11轮。现有1521万参数中约90%在全连接部分。以上支持先恢复选模方向和精简分类头，不支持保证新分数。

## 4. 检查范围

使用jitiaosai进行轻量检查；测试先看到旧代码不满足严格AUROC分支/400万参数预算，再修改并复测。

- 新结构前向形状、有限数值、参数量。
- 固定输入下现有旧权重输出逐元素不变；旧三层、窄五层也与Git中的旧定义逐元素一致。
- 五层卷积迁移、新分类头不被旧分类头覆盖、精简结构完整续训。
- 分组学习率正确、每个参数恰好属于一个优化器组。
- 合成张量反向传播、梯度上限及NaN拒绝；不调用优化器step，不训练真实数据。
- 新权重保存/加载往返，验证指标和epoch随权重记录。
- 执行真实每轮尾部逻辑：AUROC升而ACC降会保存；AUROC降或相等不会因ACC/AUPRC升而保存。
- 调度和早停只用候选AUROC；候选落后于旧冠军仍保留自己的最佳，正式冠军受保护。
- 训练逻辑不产生submission.csv。

独立代码审查重点检查了兼容加载、AUROC条件、优化器分组，并指出候选/正式冠军记录需明确区分。先用回归复现失败，再添加明确的项目相对路径及candidate_best结构；复测26项全部通过，审查复核通过，无剩余重要问题。

真实提分、完整训练耗时和官方环境端到端延迟未验证。未进行官网提交。后续由用户运行train，再单独运行predict。
