# 2026-11-01 三路线训练与两份提交计划

## 目标与选择规则

分别训练 `submission2`、`submission3`、`submission4`，每次只运行一个 GPU 任务，优先给新路线 `submission4` 留出完整验证时间。三条路线统一用**未参与训练的官方 valid 连续概率 AUROC**选各自最佳轮，再比较这三个最佳轮，选最高两条路线各生成一份官方 test CSV。官网测试分数与历史测试预测不参与模型选择。不能预先保证超过 10 月 31 日平台成绩。

现有可回退文件为 `submission2/submission.csv` 和 `submission3/submission.csv`，不得在候选通过核验前覆盖。旧 PTH、配方、CSV 哈希与官网成绩详见 `训练结果.md` 和 `AI_HANDOFF.md`。

## 顺序和资源

1. 开始前记录三条路线当前代码、RECIPE、数据文件数量与 SHA；检查所有 Python 训练/预测进程及 `nvidia-smi`，与共享 GPU 的胸片任务协商空闲时段。只读原始数据和 junction 目标。
2. `submission4` 是新架构实验，优先安排足够时间完成至少一个完整 epoch 和官方 valid 评估。默认微批量 2、累积 16、BF16、最多 12 轮；若实际耗时不允许，缩短**新 run** 的总轮数并更新其配置，不能更改已有 run 配方后继续。OOM 时减少微批量、重新建 run。每轮看官方 valid AUROC，退化时按早停规则停止。
3. `submission2` 与 `submission3` 保留现有配方，各进行短轮续训或从正式起点开同配方新 run；先读各自 RECIPE、history 和进程，禁止重复启动同一轮。优先验证新 `submission4` 的可行性，不把模型已训练过的样本用作独立验证。
4. 最晚在计划提交前预留足够时间给两次 5855 张预测、计时、CSV 校验及版本提交。任何新路线若达不到速度限制，不进入最终两份。

## 输出核验

- 对每条入选路线记录 run、epoch、官方 valid AUROC、配方 ID、模型权重 SHA256、CSV SHA256、预测生成时间。
- 每份 CSV 必须严格 5855 行；表头 `Image_name,Probability,Pred_Label`；名称和顺序与官方 `test.csv` 一致；概率有限且在 0–1；标签由六位小数概率按 0.5 得出；两份 CSV 内容不同。
- `submission4` 必须显式指定已验证的 `candidate_best.pth` 运行 `predict.py`。推理和计时共用 `score_batch`，不使用 TTA。
- 更新 `训练结果.md`、`使用说明.md`、`AI_HANDOFF.md` 与各路线 RECIPE 的实际执行结果；没有训练或没有提高时如实记录。Git 中间版本位固定 `22`，提交末位逐次加一。
