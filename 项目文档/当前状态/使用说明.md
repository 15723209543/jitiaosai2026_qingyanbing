# 当前使用说明（2026-10-30）

项目根目录只保留两份数据、`submission`、`submission2`、`submission3`、`项目文档`、两份比赛 PDF 与根 README。Git 所需隐藏项 `.git`、`.gitignore`、`.gitattributes` 保留。原始数据及 junction 目标只读。

## 提交格式

依据根目录比赛 PDF 和 [提交格式说明](../数据格式示例/2026提交格式与本地运行说明.md)，初赛仅上传 UTF-8 的 `submission.csv`。CSV 三列为 `Image_name`、`Probability`、`Pred_Label`，共 5855 行，必须按官方 test 顺序。`code/train.py`、`code/predict.py`、`code/model.py`、`code/utils.py`、`code/requirements.txt`、`cost.py` 和通过验证晋升的 `model/best_model.pth` 属于本地/复赛模型包。训练中的 `runs/` 不推送。

## 三个模型目录

- `submission/`：正式模型。其权重和 CSV 未在这次整理中改变。
- `submission2/`：focal + margin pairwise AUC 候选，`python submission2/code/train.py --epochs 1`。默认全量官方 train，官方 valid 只选模。仅当官方 valid AUROC 严格超过正式起点，代码才更新 `model/best_model.pth`。配方见 [submission2](submission2_RECIPE.md)。
- `submission3/`：原 `submission4/` 改名，一份训练器、两个采样模式。`python submission3/code/train.py --mode holdout --percent 80 --epochs 1` 从官方 train 抽 80%，余 20% 只作内部诊断；`--mode independent` 从官方 train 独立抽两份 80%。两骨干在同一批次共享融合损失，一个优化器联合训练分类头。正式选模始终只看未参与训练的官方 valid AUROC。配方见 [submission3](submission3_RECIPE.md)。

`--percent` 可输入 1–99，默认 80 位于 `submission3/code/joint_train.py` 的 `DEFAULT_PERCENT`。两种内部指标由于正式模型曾见过官方 train，不作为独立泛化指标。训练会写到本地 `runs/`；续训使用相同参数加 `--resume submission3/runs/<原run目录>`。原 `submission5/` 的旧进度已压缩归档，不能以新配方恢复。

## 预测与归档

两份候选预测已分别放在 `submission2/submission.csv` 和 `submission3/submission.csv`，都没有晋升权重。若需复现候选预测，显式传入本机 `runs/<run>/candidate_epoch1.pth`：

```powershell
python submission2/code/predict.py submission2/submission.csv --checkpoint submission2/runs/20261030_160656_195989/candidate_epoch1.pth
python submission3/code/predict.py submission3/submission.csv --checkpoint submission3/runs/20261030_164052_879617/candidate_epoch1.pth
```

初赛提交时选择要上传的**一份** CSV，并保持文件名 `submission.csv`；这两份候选均未证明比正式模型更优。正式模型路径为 `submission/model/best_model.pth`。旧模型 ZIP、迁移备份、PyCharm/临时测试/日志的 ZIP 只在忽略的 `项目文档/归档_本地/`。历史说明保存在 `项目文档/历史研究记录/`，其旧路径与旧状态仅供追溯。
