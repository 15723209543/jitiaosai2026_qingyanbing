**可以换模型。我建议首先尝试“ResNet-18残差网络＋更高分辨率输入”，不再继续给当前五层CNN简单加层。**

但必须说清楚：**AUROC≥0.98可以作为目标，不能在训练和测评之前保证。**别人取得98、99分说明值得继续探索，但不能证明换某个网络就必然达到。我们要提高的是独立数据上的真实表现，而不是通过混合训练集、验证集把数字抬高。

## 一、三个可选方案

它们仍然属于CNN，但结构比现在的顺序卷积网络更成熟。

| 方案              | 模型              | 相比当前模型的主要变化                                       | 代价与风险                                 |
| ----------------- | ----------------- | ------------------------------------------------------------ | ------------------------------------------ |
| **A：推荐先做**   | **ResNet-18**     | 引入残差连接、批量归一化；更深的网络不必每层都重新学习全部信息 | 计算量增加；仍需控制过拟合                 |
| B：偏重轻量部署   | MobileNetV3-Large | 使用轻量卷积、通道注意力和适配的激活函数                     | 运算量较低不代表本机一定更快；效果需要实测 |
| C：另一条性能路线 | EfficientNet-B0   | 结合残差、通道注意力，协调网络深度与宽度                     | 训练与调参更复杂，不能预先认定优于A        |

这些网络均有 Torchvision 官方实现，不需要引入一堆新框架。[ResNet-18](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)、[MobileNetV3](https://docs.pytorch.org/vision/0.25/models/generated/torchvision.models.mobilenet_v3_large.html)、[EfficientNet-B0](https://docs.pytorch.org/vision/0.25/models/generated/torchvision.models.efficientnet_b0.html)。

**为什么先推荐A？**残差连接就是在计算结果中保留原输入，使网络学习“需要修正什么”，缓解深层网络难以优化的问题。这比单纯叠加普通卷积层更有明确依据，而且便于你继续理解和维护代码。[ResNet原论文](https://arxiv.org/abs/1512.03385)

## 二、必须先遵守的比赛限制

官网要求：只使用主办方数据，不允许外部标注数据；模型总大小≤500MB，单张端到端延迟≤100毫秒。[官方规程](https://www.ncccu.org.cn/index/Paper/case2.html)

**外部预训练权重是否允许，规则没有单独明确。**所以默认方案是：

- 使用成熟的网络结构，但设置`weights=None`，从随机参数开始训练。
- 不自动下载ImageNet预训练权重。
- 如果主办方明确允许预训练，再另外制定迁移学习方案。

注意：**当前五层CNN的权重不能直接当作ResNet的预训练权重。**新网络需要重新训练，原来的92分模型保留作比较基准。

## 三、方案A的具体执行方案

以下是第一组实验的起点，不是已经验证过的最优参数。

### 1. 模型与图片

- 模型：ResNet-18，输出改为两个类别。
- 分类部分：全局平均池化＋`Dropout(0.2)`＋二分类输出。
- 保留网络原有的BatchNorm和ReLU，不同时替换所有激活函数。
- 图片先使用 **128×128**，成功后再独立比较 **160×160**。

当前64×64压缩较强。提高分辨率可能保留更多可用于分类的细节，但这只是需要实验验证的假设，不能认定它就是目前分数的唯一瓶颈。

### 2. 第一组训练参数

| 项目         | 初始方案                                           |
| ------------ | -------------------------------------------------- |
| 每批图片数量 | 32张，之后按实测内存和速度调整                     |
| 优化器       | AdamW                                              |
| 学习率       | 前2轮从`3e-5`升至`3e-4`，之后逐步下降              |
| 权重衰减     | `1e-4`                                             |
| 损失函数     | 普通交叉熵                                         |
| 类别不平衡   | 先保留均衡采样，不再叠加大类别权重                 |
| 梯度截断     | 保留范数上限5                                      |
| 训练上限     | 30轮；完成前10轮后，若连续8轮验证AUROC未提高则早停 |
| 模型保存     | **只按独立验证集AUROC严格提高保存**                |

这里增加训练预算，是因为新架构从零开始学习，不能直接套用旧模型续训的轮数；**不是靠延长训练来掩盖无效改动。**

### 3. 数据增强

先采用温和的增强：

- 水平翻转；
- 小角度旋转，例如±15°；
- 轻微亮度、对比度变化。

暂不使用大幅裁剪、强烈颜色变化或随机遮挡。验证集、测试集使用固定预处理，不能随机增强后直接与旧成绩比较。

## 四、怎样一步步向0.98推进

**不要同时训练三个网络，也不要一次改十几个变量。**

1. **保护基准**：保留现有92分模型、配置、CSV和记录。
2. **先检查速度与兼容性**：少量前向、反向检查和单张测速，确认没有代码问题，再由你启动正式训练。
3. **训练A方案**：得到ResNet-18在128像素下的独立验证成绩。
4. **单独比较160像素**：检查是否真正改善AUROC，以及推理耗时是否符合要求。
5. **对表现最好的配置换一个随机种子复验**：避免只依赖一次幸运结果。
6. **仍有明显瓶颈，再比较C方案**。只有不同模型确实互补，且总推理耗时达标，才考虑两个模型的概率平均。

**达到验证AUROC 0.98，不代表官方测试必然也达到0.98；最终仍需官方结果验证。**如果某一步退步，就保留原模型，不强行替换。

## 五、项目组织保持不变

- `model.py`：网络定义，直接运行打印结构。
- `train.py`：训练、验证、保存权重，不生成答案CSV。
- `predict.py`：加载模型，生成提交CSV。
- `utils.py`：必要的数据、配置和兼容工具。
- 训练记录继续存到`项目文档/训练记录`。
- 新旧模型各自记录输入尺寸和预处理配置，避免把旧64像素模型误用到新输入流程。
