# v1.5.3 八组双模型实验与操作

本轮只提供可运行代码，**不正式训练、不生成最终答案**。原`submission/`的旧模型、配置和CSV保留不变；这八组是实验候选，不能根据模型名称预先断言哪组最高分。只使用主办方`glaucoma_first/`中的train/valid/test，不使用外部图片、标注或预训练权重。模型均通过`torchvision`构建且`weights=None`。

本机`jitiaosai`已验证的实际版本为PyTorch 2.13.0+cpu、torchvision 0.28.0+cpu；八组的`requirements.txt`据此记录。`deepStudy`和原`submission/`的依赖文件未修改。

## 八组配对

| 编号 | 模型1 | 模型2 | 选择理由 |
|---|---|---|---|
| 01 | ResNet-18 | MobileNetV3-Large | 残差基线＋轻量网络 |
| 02 | ResNet-18 | EfficientNet-B0 | 残差网络＋复合缩放网络 |
| 03 | ResNet-18 | DenseNet-121 | 残差连接＋密集连接；尤其要核实速度 |
| 04 | ResNet-18 | RegNetY-400MF | 残差基线＋规则化轻量网络 |
| 05 | EfficientNet-B0 | MobileNetV3-Large | 两种高效网络，但特征可能相关 |
| 06 | EfficientNet-B0 | RegNetY-400MF | 复合缩放＋规则化网络 |
| 07 | DenseNet-121 | MobileNetV3-Large | 密集连接＋轻量网络 |
| 08 | MobileNetV3-Large | RegNetY-400MF | 两种轻量网络，优先检验速度余量 |

五种模型有十种两两组合；本轮优先实现上列八种，不实现DenseNet＋EfficientNet及DenseNet＋RegNet（本机小样本单张测速显示DenseNet组合有较高超时风险）。MobileNet＋RegNet作为轻量速度对照，即使速度好也不代表AUROC好。这些不是已经测得的准确率排名。

## 每套目录与职责

`NN/code/model.py`：todo1读取数据、todo2定义两个模型，`MODEL_NAMES`是八套代码间唯一需要改变的架构配对行；直接运行只打印两个网络参数。`NN/code/train.py`：todo3独立训练或复用两个模型，逐轮打印loss、acc、验证AUROC/AUPRC，最后打印等权双模型的验证结果，**不写答案**。`NN/code/predict.py`：todo4加载本方案两份参数，把阳性概率`(p1+p2)/2`写入`NN/results/submission.csv`，字段仍为`Image_name,Probability,Pred_Label`。`NN/code/utils.py`：读取、增强、采样、指标、权重与CSV工具。`NN/model/`存两个以架构命名的`.pth`；空目录由`.gitkeep`保留。训练曲线放`项目文档/训练记录/NN/`，不放`results/`。

## 推荐操作顺序

1. 用`jitiaosai`解释器依次运行`01/code/train.py`、`02/code/train.py`、`03/code/train.py`、`04/code/train.py`。正常情况下共训练ResNet-18、MobileNetV3-Large、EfficientNet-B0、DenseNet-121、RegNetY-400MF五种单模型；同名权重会从已有编号方案核验配置后复制，不再次训练。
2. 再运行`05`～`08`各自的`train.py`。已有的相同单模型权重会复用；每套仍独立验证自己的双模型组合。若随机运行顺序也能工作，但可能造成重复训练。
3. 记录八组的独立验证AUROC、AUPRC及两份权重大小；比较时不要用训练Acc决定冠军。同一`valid/`既用于每轮保存也用于组合比较，差距很小时有选模偏差，不能承诺官网分数提升。
4. 先做单张真实图片端到端测速。两个模型文件**合计未压缩大小≤500MB**，单张读图、预处理、双模型前向与概率输出须符合**≤100ms**；未经测试的组合不能宣布合规。若双模型没有优于最佳单模型或超时，选择单模型而不是强行融合。
5. 只有决定要提交某组时，单独运行该编号的`predict.py`；它才生成该组的CSV。无标签`test/`不能计算真实准确率；上传前检查CSV行数、列名及文件名。原`submission/results/submission.csv`不会被这八组覆盖。

已有参数默认跳过重复训练；如需对某套已有参数重新实验，把其`train.py`的`RETRAIN_EXISTING`设为`True`，程序会先备份原参数，仍仅以验证AUROC严格提高替换。若修改图片尺寸、增强、采样、学习率或训练数据，必须同步改变`utils.py`的`RECIPE`标记，阻止与旧训练配方误复用。`deepStudy`解释器不动。

## 本机轻量测速，仅供筛选

在当前本机以4个CPU线程、随机初始化的网络、前两张预热、随后8张实际测试图抽测；每张时间含读图、解码、128像素处理、两个前向和概率计算，**不含程序启动、模型加载及整份CSV写盘**。下表不是正式训练成绩，也不能证明在比赛环境中每张都≤100ms。

| 方案 | 8张平均/最大毫秒 |
|---|---|
| 01 | 54.4 / 69.6 |
| 02 | 57.5 / 69.6 |
| 03 | 90.7 / 114.0 |
| 04 | 54.8 / 69.0 |
| 05 | 55.6 / 81.0 |
| 06 | 59.0 / 73.1 |
| 07 | 86.8 / 100.3 |
| 08 | 51.9 / 68.0 |

03、07在这个**很小的本机样本**中已有超过100ms的图片；它们是准确率候选而不是可直接宣称符合时延约束的提交方案。训练后必须用最终权重、目标硬件和更多图片复测；如仍超时，就不能选它们作为最终双模型。不同机器和并发状态会影响时间。

## 论文依据与边界

五个结构分别来自[ResNet/CVPR 2016](https://openaccess.thecvf.com/content_cvpr_2016/html/He_Deep_Residual_Learning_CVPR_2016_paper.html)、[DenseNet/CVPR 2017](https://openaccess.thecvf.com/content_cvpr_2017/papers/Huang_Densely_Connected_Convolutional_CVPR_2017_paper.pdf)、[MobileNetV3/ICCV 2019](https://openaccess.thecvf.com/content_ICCV_2019/papers/Howard_Searching_for_MobileNetV3_ICCV_2019_paper.pdf)、[EfficientNet/ICML 2019](https://proceedings.mlr.press/v97/tan19a.html)、[RegNet/CVPR 2020](https://openaccess.thecvf.com/content_CVPR_2020/html/Radosavovic_Designing_Network_Design_Spaces_CVPR_2020_paper.html)。[CCF官方目录](https://www.ccf.org.cn/Academic_Evaluation/AI/)把CVPR、ICCV、ICML列为A类会议，但论文出处不等于本赛题模型的实际AUROC。直接研究眼底青光眼的[AG-CNN/CVPR 2019](https://openaccess.thecvf.com/content_CVPR_2019/html/Li_Attention_Based_Glaucoma_Detection_A_Large-Scale_Database_and_CNN_Model_CVPR_2019_paper.html)依赖额外医生注意力标注，本赛题不能原样照搬。[赛项官网](https://www.ncccu.org.cn/index/Paper/case2.html)以AUROC为主，平局看AUPRC，并规定初赛只提交CSV。
