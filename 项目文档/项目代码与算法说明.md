# 2026 青光眼分类项目代码与算法说明

更新日期：2026-10-13

## 1. 项目目标与官方规则

本项目对彩色眼底图片进行二分类，输出图片属于青光眼阳性类别的概率。标签 `1` 表示
阳性，标签 `0` 表示阴性。2026 年赛项一提供训练集 51396 张、验证集 5849 张、
测试集 5855 张；图像为 JPG/PNG，尺寸不固定，阳性样本比例极低。

初赛不再上传代码等待服务器运行，而是在本地完成训练和预测，只上传 UTF-8 编码的
`submission.csv`。复赛需要同时提交预测结果和模型。

官方评分以 AUROC 为主要指标、AUPRC 为辅助指标。二者都依赖连续概率，因此 CSV
中的 `Probability` 必须是“阳性类别 1 的概率”，不能写成最大类别置信度。
平台显示的 `50.00` 是评分，不应直接解释成“50% 的图片分类正确”。本地准确率、
AUROC、AUPRC 和平台分数分别记录，不能互相替代。

仍沿用课堂逻辑。2026 规程带来的必要修改是：独立验证集、本地预测、固定结果路径、

ANN 和课程 Markdown 仍只提供增加深度、Dropout、标准化和 Adam 等优化依据，不替代
CNN 主体。

## 4. model.py

### 4.1 create_dataset()

来源：复用课堂 CNN 的 todo1。

作用：调用 `utils.load_train_data()`，返回 `train_dataset` 和 `valid_dataset`。
若已放入官方验证集，使用官方验证集；否则工具函数才进行临时 8:2 分层划分。

### 4.2 ImageModel.__init__()

来源：复用课堂 CNN 的网络定义，并参考课堂优化资料增加层数和参数量。

模型结构：

```text
输入 RGB：3 × 64 × 64
→ Conv2d(3, 32, 3) → ReLU → MaxPool2d(2)       = 32 × 31 × 31
→ Conv2d(32, 64, 3) → ReLU → MaxPool2d(2)      = 64 × 14 × 14
→ Conv2d(64, 128, 3) → ReLU → MaxPool2d(2)     = 128 × 6 × 6
→ reshape                                           4608
→ Linear(4608, 2048) → ReLU → Dropout(0.5)
→ Linear(2048, 2048) → ReLU → Dropout(0.5)
→ Linear(2048, 2)                                  两类 logits
```

总参数约 1373 万，float32 参数文件约 54.9MB，低于规程的 500MB 上限。

### 4.3 ImageModel.forward(x)

来源：复用课堂 CNN 的前向传播。

依次完成三次“卷积加权求和 → ReLU 激活 → 最大池化”，再拉平并通过两层带 Dropout
的全连接网络。输出层不执行 Softmax，因为训练使用的 `CrossEntropyLoss` 已包含
相应的概率计算。

### 4.4 main

直接运行 `model.py` 时，只调用 `torchsummary.summary` 打印每层形状和参数量，不
训练、不预测、不生成模型或 CSV。

## 5. train.py

### 5.1 train(train_dataset, valid_dataset)

来源：复用课堂 CNN 的 todo3。仍使用原前向传播、交叉熵、Adam 和反向传播循环；
新增均衡采样、进度输出、验证比较和最佳模型保存。

流程：

1. 固定 PyTorch 随机种子为 0，设置 CPU 线程数为 8；
2. 创建 batch size 为 64 的 DataLoader，使用均衡采样器，不再设置 `shuffle=True`；
3. 创建 `ImageModel`；若 `RESUME=True` 且已有 `.pth`，先加载并验证旧模型；
4. 将训练前模型的指标记为 `epoch=0`，作为本轮比较的起点；
5. 创建普通 `CrossEntropyLoss`，均衡采样后不再额外加权损失；
6. 创建 Adam，学习率 `1e-4`，默认继续训练 3 轮；
7. 对每批数据执行前向传播、损失计算、梯度清零、反向传播和参数更新；
8. 首批、每 25 批和末批立即打印进度；每轮结束打印平均损失、训练准确率和时间；
9. 每轮调用 `predict.evaluate(valid_dataset, model)` 验证当前模型；
10. 先比较验证 AUROC，相同时比较梯形 AUPRC，仅在改善时保存最佳 `.pth`；
11. 更新 `training_history.csv` 和 `config.json`，打印本次保留模型的验证结果。

每轮抽取 51396 次，因此 batch size 为 64 时共 804 批。终端输出保留课堂的
`epoch/loss/acc/time` 字段，同时显示当前批次、完成百分比和预计剩余时间。以下仅为
输出形状示意，尖括号是运行时数值，不是实测结果：

```text
训练程序已启动, 正在加载PyTorch和数据读取模块...
开始训练 epoch: 1/3
epoch: 1/3, batch: 25/804 (3.1%), time:<秒>, remaining:<分钟>min, loss:<损失>, acc:<准确率>
epoch: 1, loss: <损失>, acc:<准确率>, time:<秒>s
开始验证: 5849张有标签图片
Acc: <准确率>, AUROC: <数值>, AUPRC(梯形): <数值>, AP: <数值>
阳性召回率: <百分比>, 特异度: <百分比>, TP:<数量> TN:<数量> FP:<数量> FN:<数量>
```

所有进度均使用 `flush=True`，不再等整轮完成才出现第一条信息。剩余时间按照已完成
批次的平均耗时估计，首次读取图片与后续命中缓存的速度不同，估计值会变化。

### 5.2 均衡采样与续训原理

训练集阴性 49739 张、阳性 1657 张。若类别 `c` 的数量为 `n_c`，该类每张图片的
抽样权重为：

```text
sample_weight = 1 / n_c
```

两个类别的总抽样权重都为 1，因此每次抽到阳性、阴性的概率各约一半。这是有放回
随机采样，不保证每批严格各一半，也不保证一轮中每张原图都出现一次。阳性图片会被
重复抽到，因此只对训练数据使用随机水平翻转；验证集和测试集不做随机增强。

上一版使用 batch=8 和加权交叉熵，绝大多数批次没有阳性；加权损失默认按每批的权重
总和归一化，全阴性批次中类别权重会抵消。本版改用均衡采样与普通交叉熵，直接改变
每批接触到的样本分布。均衡采样后的训练 `acc` 与上一版自然分布上的 97% 不能直接
比较，应重点比较同一个官方验证集上的 AUROC、AP、召回率等指标。

`RESUME=True` 表示从已保存模型权重继续训练，但 Adam 的内部状态重新初始化，
不是恢复上次运行的完整中断点。将其改为 `False` 才会从随机初始化开始。每次运行的
轮次从 1 重新计数；`best_epoch_this_run=0` 表示训练后仍保留运行前的模型。

最佳模型保存时先写 `best_model.tmp`，完整写入后替换 `best_model.pth`。验证指标
不如原模型时不覆盖参数，最后一轮不一定是最终使用的模型。

### 5.3 main

直接运行 `train.py` 时：

```text
打印启动信息 → create_dataset
→ train：可选验证旧参数 → 训练一轮 → 验证 → 保存最佳参数/训练记录（共3轮）
→ predict：重新读取最佳参数 → 预测无标签test → 生成submission.csv
```

`train.py` 结束时会自动生成提交 CSV，无需为了得到本次结果再手动运行一次
`predict.py`。每轮 `Acc` 来自有标签的 `valid/`，不是无标签 `test/` 的真实准确率。

## 6. predict.py

### 6.1 evaluate(test_dataset, model=None)

来源：复用课堂 CNN 的 todo4。

由 `train.py` 每轮调用。传入 `model` 时直接验证当前参数；未传入时才从
`best_model.pth` 加载模型。函数切换 `eval()` 并使用 `torch.no_grad()` 关闭梯度，
按不打乱的顺序收集真实标签及 `softmax(output)[:, 1]`，调用
`utils.calculate_metrics()`，返回含指标的字典，并打印验证进度和效果。

返回字段包括：

```text
accuracy / auroc / auprc / ap / recall / specificity / tp / tn / fp / fn
```

其中 `auprc` 为 PR 曲线梯形积分，`ap` 为平均精度，计算定义不同，不能互称。
详细定义见第 7.8 节。验证不会更新模型权重。

### 6.2 predict(test_dir, output_csv)

来源：复用课堂测试循环，按 2026 规程改为本地无标签预测。

提交路径保持固定：

```text
test_dir  = 项目根目录/glaucoma_first/test
output_csv = submission/results/submission.csv
```

流程：

1. 读取 `test.csv`，按官方 `Image_name` 顺序匹配 JPG/JPEG/PNG 图片；
2. 创建不打乱顺序的 DataLoader；
3. 加载 `best_model.pth`；
4. 切换 `eval()` 并关闭梯度；
5. 对 logits 执行 Softmax；
6. 只提取 `softmax(output)[:, 1]`，即阳性类别概率；
7. 调用工具写出官方 CSV；
8. 打印预测进度、生成路径、图片总数及预测为阳性的数量。

`test.csv` 只有 `Image_name/Age`，没有 `True_Label`，所以此阶段无法给出真实
准确率或 AUROC。需要用官方有标签 `valid/` 观察模型效果，测试集最终成绩由平台给出。

### 6.3 main

直接运行 `predict.py`，不再需要服务器传入位置参数。main 只调用 `predict()`，最终
生成可直接上传的 `submission.csv`。

## 7. utils.py

工具函数均是为本项目的数据接口、训练管理和结果格式编写；`Dataset` 的标准方法
沿用 PyTorch 常规写法，具体来源也标在对应代码前。

### 7.1 ImageDataset.__init__(image_paths, labels=None, training=False)

保存图片路径和可选标签。有标签时用于训练/验证，无标签时用于最终预测。
`training=True` 选择随机水平翻转加标准化变换；其余情况使用确定性变换。同时创建
当前数据集对象的内存缓存，不向数据目录写入额外图片。

### 7.2 ImageDataset.__len__()

返回数据集样本数量，供 PyTorch DataLoader 计算批次数。

### 7.3 ImageDataset.__getitem__(index)

第一次访问某张图片时，先请求 JPEG 解码器按 64×64 附近尺寸读取，转换为 RGB，
以双线性插值缩放为 64×64 并缓存在内存。再次访问直接使用缓存，避免重复解码大图。
缓存保存的是未随机增强的 RGB 图片，每次训练取样仍重新决定是否水平翻转，然后执行
`Resize → ToTensor → Normalize`。有标签时返回 `(x, y)`，无标签时只返回 `x`。

训练和验证共 57245 张，若全部进入缓存，按每像素 3 字节估算的 RGB 像素数据约
671 MiB；实际进程内存还包括图像对象、索引、模型、梯度和优化器。缓存按需填充，
不预先复制完整数据集到磁盘；程序退出后释放。验证/测试没有随机翻转。

### 7.4 _load_labeled_images(csv_path, image_dir)

读取一份有标签 CSV，检查 `Image_name/True_Label` 字段、图片是否存在以及标签是否为 0/1，
返回图片路径和标签。该内部函数避免训练集与验证集读取代码重复。
CSV 中 `.jpg` 与真实文件的 `.JPG` 通过忽略大小写匹配，兼容大小写敏感文件系统。

### 7.5 load_train_data()

读取 `glaucoma_first/train.csv` 和 `glaucoma_first/valid.csv`，分别匹配 `train/` 和
`valid/` 图片目录，分别构建启用训练变换和确定性验证变换的数据集。只有缺少官方
验证 CSV 时，才按类别以固定随机状态做 8:2 分层切分。

### 7.6 create_sampler(labels)

统计两个类别的数量，给每张样本设置其类别数量的倒数作为权重，返回
`WeightedRandomSampler`。每轮抽取次数等于训练集原始数量，允许重复抽取。
训练数据缺少任一类别时立即报错。本函数替代旧的 `calculate_class_weight()`，
不会再给 `CrossEntropyLoss` 传类别权重。

### 7.7 print_progress(stage, batch_idx, batch_count, start, detail="")

训练、验证和预测共用的进度输出。第 1 批、每 25 批及最后一批打印阶段名、批次、
完成百分比、已用时间和预计剩余分钟数；训练另外传入累计平均损失和准确率。
`LOG_EVERY` 控制打印间隔，`flush=True` 让终端即时显示。

### 7.8 calculate_metrics(labels, positive_probability)

检查验证标签包含 0/1 两类且概率为有限值，使用 scikit-learn 计算：

| 字段 | 定义或作用 |
|---|---|
| accuracy | `(TP+TN)/总数`，即普通分类准确率 |
| auroc | `roc_auc_score`，根据连续阳性概率评估类别排序 |
| auprc | 先生成 precision-recall 曲线，再以 `auc(recall, precision)` 做梯形积分 |
| ap | `average_precision_score`，按召回率增量加权的平均精度，不是梯形积分 |
| recall | `TP/(TP+FN)`，阳性召回率，也称 sensitivity |
| specificity | `TN/(TN+FP)`，阴性正确识别比例 |
| tp / tn / fp / fn | 以概率 0.5 为分类阈值的混淆矩阵数量 |

AUROC、梯形 AUPRC 和 AP 使用连续概率；准确率、召回率和特异度使用 0.5 阈值。
本地同时列出两种 PR 汇总值，避免把历史 AP 误称为梯形 AUPRC；平台最终以其官方
计算实现为准。对阳性稀少数据，不能只用 Accuracy 判断训练是否有效。

### 7.9 save_training_record(history, best_metrics, best_epoch)

每轮写入 `submission/results/training_history.csv`，记录本次运行已完成各轮的
训练损失、训练准确率及验证指标。加载旧参数时还包含 `epoch=0` 的验证记录，该行
没有训练损失或训练准确率。

同时更新 `submission/model/config.json`，保存图片尺寸、batch size、本次计划
轮数、续训开关、采样方式、最佳轮次和最佳验证指标等。历史表每次运行记录本次过程，
不自动追加前次运行；`best_epoch_this_run=0` 明确表示旧参数仍最佳。这两个文件
用于本地查看，不上传初赛平台。

### 7.10 load_test_data(test_dir, test_csv)

读取官方 `test.csv`，按其中的 `Image_name` 顺序匹配测试目录中的 JPG/JPEG/PNG，
构建无标签 ImageDataset；匹配时忽略 `.jpg/.JPG` 大小写差异，写回 CSV 时保留官方名称。

### 7.11 write_submission(image_names, positive_probability, output_csv)

写出 UTF-8 CSV。字段严格为：

```text
Image_name, Probability, Pred_Label
```

检查文件名数量与概率数量一致，概率有限且位于 `[0,1]`，再写文件。阳性概率先保留
6 位小数，再按是否大于等于 0.5 得到 `Pred_Label`，避免显示 `0.500000` 却写标签
0 的精度边界问题。函数返回实际输出路径。

## 9. 提交 CSV 的算法

对于模型输出 `z_0,z_1`，阳性概率为：

```text
Probability = exp(z_1) / (exp(z_0) + exp(z_1))
```

标签为：

```text
Pred_Label = 1, Probability >= 0.5
Pred_Label = 0, Probability < 0.5
```

示例：若阴性概率为 0.88、阳性概率为 0.12，CSV 必须写 `Probability=0.12` 和
`Pred_Label=0`，不能写最大置信度 0.88。
