# 终端输出与评价指标说明

更新日期：2026-10-15；适用代码 V1.3.1。本文解释终端信息，供运行时查阅。

V1.3.1开始会打印“本轮训练模型: 5层卷积, 通道32→64→128→256→512”，指本次候选模型，不代表磁盘最佳模型已经加宽。接着先验证磁盘上的原模型；新模型的完整验证集准确率严格提高才保存。

先记住：小写 `acc` 看训练过程，大写 `Acc` 看验证集。按用户要求，本地保存最佳模型只依据验证 `Acc`；比赛主要评价仍是 `AUROC`，两者不是同一回事，同时观察 `AUPRC`、`AP` 和阳性召回率。`loss` 是训练优化的目标，`time`、`remaining` 是时间信息。

本文解释新版输出，不代替真实训练结果。`train.py` 负责训练和验证；用户单独运行 `predict.py` 才生成提交答案。本次助手没有训练。

## 1. 常见字段速查

| 终端字段 | 中文含义 | 当前项目中具体指什么 | 怎么看 |
|---|---|---|---|
| `epoch` | 轮次 | 本次运行的第几轮训练 | `2/12` 表示第 2 轮，最多 12 轮，可提前停止 |
| `lr` | 学习率 | 这一轮参数更新使用的步长 | `5.00e-05` 就是 0.00005，不是准确率 |
| `batch` | 批次 | 当前阶段处理完的批次数 | `25/804` 表示本轮已处理 25 批 |
| `(3.1%)` | 进度百分比 | 已完成批次数 ÷ 本阶段总批次数 | 是处理进度，不是准确率 |
| `loss` | 损失 | 本轮训练到当前为止的平均交叉熵损失 | 同样设置下通常越低越好，但还要看验证效果 |
| `acc` | 训练准确率 | 本轮已经抽取并训练的样本中，预测正确的比例 | `0.8599` 表示约 85.99% |
| `Acc` | 验证准确率 | 完整有标签验证集上预测正确的比例 | `0.9152` 表示约 91.52%，不等于阳性召回率 |
| `AUROC` | ROC 曲线下面积 | 模型把阳性排在阴性前面的能力 | 0～1，越高越好；随机排序约 0.5 |
| `AUPRC(梯形)` | PR 曲线下面积 | 不同阈值下，查得准与查得全的综合表现 | 0～1，越高越好；这里采用梯形积分 |
| `AP` | 平均精度 | 另一种汇总整条 PR 曲线的方法 | 0～1，越高越好；不等于 Accuracy，也不等于梯形 AUPRC |
| `阳性召回率` | Recall / Sensitivity | 所有真实阳性中，被正确发现的比例 | 越高表示漏掉的阳性越少；要同时观察误报 |
| `特异度` | Specificity | 所有真实阴性中，被正确判为阴性的比例 | 越高表示阴性被误报的比例越低 |
| `TP/TN/FP/FN` | 四种分类结果的数量 | 正确识别阳性、正确识别阴性、误报、漏报 | 具体解释见第 4 节 |
| `time` | 已用时间 | 当前轮训练、当前验证或当前测试预测已经用的时间 | `s` 是秒，不是累计全部程序时间 |
| `remaining` | 预计剩余时间 | 按当前平均速度估算，本阶段还要多久 | `min` 是分钟，是动态估计值 |
| `valid` | 验证阶段 | 正在处理有真实标签的 `valid/` 图片 | 用来检查模型效果，不更新模型权重 |
| `test` | 测试预测阶段 | 正在预测没有公开标签的 `test/` 图片 | 最后生成 CSV，不能计算真实测试准确率 |

注意单位：`acc:0.85` 是 85%，不是 0.85%；但 `AUROC:0.85` 不能解释成“85% 的图片分类正确”。

## 2. 训练行应该怎样读

下面是按当前设置写的输出示例，数字用于说明格式，不是一次新的训练结果：

```text
开始训练 epoch: 1/12, lr:5.00e-05
epoch: 1/12, batch: 25/804 (3.1%), time:50.0s, remaining:26.0min, loss:0.45000, acc:0.7800
```

这表示：本次最多训练 12 轮，目前是第 1 轮，学习率为 0.00005；本轮共 804 批，已完成 25 批，约完成 3.1%；本轮已花 50 秒，估计还要 26 分钟；平均损失为 0.45，累计训练准确率为 78%。

### 2.1 epoch：一轮训练

当前训练集有 51396 张图片，`BATCH_SIZE=64`，每轮抽取 51396 次，所以：

```text
每轮批次数 = 向上取整(51396 ÷ 64) = 804
```

最后一批不足 64 张也会参与训练。当前使用有放回的均衡采样：阳性和阴性被抽到的机会各约一半，因此一轮中某些图片会重复出现，某些图片可能没有出现，并非所有原图恰好训练一次。

当前 `utils.py` 设置 `EPOCHS=12`，这是上限。连续 5 轮未出现更佳模型会提前停止，不必跑满 12 轮。旧日志中的 3 轮、5 轮属于当时设置，不是程序错误。每次运行重新计轮。

### 2.2 loss：模型犯错的代价

当前使用普通交叉熵 `CrossEntropyLoss()`。可以理解为：模型给正确答案的概率越低，受到的惩罚越大。

对于一张图片，简化公式为：

```text
loss = -ln(模型给真实类别的概率)
```

例如，一张真实阳性图片：

| 模型给阳性的概率 | 这张图片的交叉熵损失，约值 | 含义 |
|---|---:|---|
| 0.9 | 0.105 | 给正确类别较高概率，损失小 |
| 0.5 | 0.693 | 两类各一半，区分不明确 |
| 0.1 | 2.303 | 给正确类别很低概率，损失大 |

终端里的 `loss` 是“本轮开始到现在，所有已处理样本的累计平均”，不是刚刚那一批的损失；每轮开始重新统计。v1.2.0 在 Adam 中加入 L2 权重衰减，但这里显示的 loss 仍只包含交叉熵，不包含正则项。

损失没有 1 这个上限，也不是错误率：`loss=0.2` 不表示错了 20%，`1-loss` 也不等于准确率。损失下降通常意味着模型更会拟合训练数据，但是否能识别未用于训练的图片，还要看验证指标。公式对应 [PyTorch 交叉熵文档](https://docs.pytorch.org/docs/2.10/generated/torch.nn.CrossEntropyLoss.html)。

### 2.3 acc：训练准确率

```text
acc = 本轮已处理样本中预测正确的次数 ÷ 本轮已处理样本次数
```

这里“次数”包括均衡采样重复抽到的图片。代码取两类输出中较大的一类作为预测类别，再与训练标签比较。

它同样是本轮累计平均，每轮重新统计。训练期间模型参数一直变化，且启用了 Dropout 和随机水平翻转，所以 `acc` 不是“训练结束后，用最终参数重新完整评估训练集”的准确率。

当前训练采样接近正负各半，而验证集保留原始分布，因此不能仅凭 `acc` 与 `Acc` 的高低差就断定是否过拟合。

## 3. Acc、AUROC、AUPRC、AP 的区别

下面选用项目 2026-10-13 的一段历史验证输出解释，不代表当前最新模型的成绩：

```text
Acc: 0.9152, AUROC: 0.885387, AUPRC(梯形): 0.362978, AP: 0.365991
阳性召回率: 64.40%, 特异度: 92.44%, TP:123 TN:5230 FP:428 FN:68
```

### 3.1 Acc：总体判对了多少

当前验证阶段以阳性概率 `>=0.5` 判为阳性，否则判为阴性。

```text
Acc = (正确识别的阳性数 + 正确识别的阴性数) ÷ 验证图片总数
    = (TP + TN) ÷ (TP + TN + FP + FN)
```

上面例子中 `(123+5230)/5849≈0.9152`，即验证集总体约 91.52% 判对。

但数据非常不平衡：验证集 5849 张里有 5658 张阴性、191 张阳性。即使全部猜阴性，准确率也达到 `5658/5849≈96.73%`，却一张阳性都发现不了。因此不能只追求较高的 `Acc`。

大小写只是本项目的输出约定：`acc` 用于训练，`Acc` 用于验证；不是机器学习通用的两种不同准确率公式。

### 3.2 AUROC：阳性是否被排在前面

AUROC 的全称是 Area Under the Receiver Operating Characteristic Curve，中文是 ROC 曲线下面积。

模型对每张图片输出阳性概率。改变判阳性阈值，可以得到不同的阳性召回率与阴性误报率；把这些点组成 ROC 曲线，再计算面积。

更直观地说：随机拿一张阳性和一张阴性，模型有多大机会给阳性更高的分数。相同分数的情况按半次正确排序计入。

| AUROC | 含义 |
|---|---|
| 1.0 | 在这份评估数据上，所有阳性都排在阴性前面 |
| 约 0.5 | 排序区分能力接近随机 |
| 小于 0.5 | 排序比随机还差，值得检查标签、阳性概率方向和模型效果 |

`AUROC=0.885387` 描述的是上述排序能力，不是“88.54% 的图片分类正确”，也不能直接等同于平台 88.54 分。本项目通过 `roc_auc_score` 使用连续阳性概率计算，比赛规程以 AUROC 为主要指标。[scikit-learn AUROC 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html)

只把分类阈值从 0.5 改为 0.3，若阳性概率本身不变，AUROC 不会改变。

### 3.3 AUPRC：找到阳性时，能否兼顾少误报和少漏报

AUPRC 是 Area Under the Precision-Recall Curve，即精确率—召回率曲线下面积。

理解它需要两个量：

- **Precision，精确率/查准率**：所有被模型判为阳性的图片里，有多少真的是阳性，公式为 `TP/(TP+FP)`。
- **Recall，召回率/查全率**：所有真实阳性图片里，有多少被找出来，公式为 `TP/(TP+FN)`。

降低阈值通常能发现更多阳性，同时也会增加误报。PR 曲线汇总不同阈值下两者的关系；本项目先计算 `precision_recall_curve`，再用 `auc(recall, precision)` 做梯形积分，因此终端写明 `AUPRC(梯形)`。

它越高通常越好，但 `0.362978` 不是“36.30% 的图片判对”，也不是某一个阈值下的精确率。它适合补充观察阳性稀少时的检出效果；比较时应使用同一验证集，阳性比例变化会影响 PR 指标。

### 3.4 AP：同一条 PR 曲线的另一种汇总方式

AP 是 Average Precision，中文为平均精度。当前使用 `average_precision_score`：按召回率的增量，对相应精确率加权求和。

```text
AP = 各段“召回率增加量 × 相应精确率”之和
```

AP 与梯形 AUPRC 都关注阳性检出，但面积汇总方式不同：前者不使用梯形线性插值，所以数值不必相等，也不能保证始终谁更大。这里将两者分别打印，避免混称。AP 不是 `Acc`，也不是单一阈值下的 Precision。[scikit-learn AP 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)

从V1.3.1开始，本地只在完整验证集Acc严格提高时保存模型；Acc相等不保存，不再比较AUROC或AUPRC。比赛平台的AUPRC最终以其实际实现为准，不能直接假设与本地某一个PR数值完全一致。

为什么旧版训练准确率升了却没保存？最近的8轮记录中，第3轮验证Acc约92.51%、AUROC约0.898348；第8轮验证Acc约94.72%、AUROC约0.892875。旧规则按AUROC，因此保留第3轮。训练时权重一直在更新，只是没有覆盖“最佳模型”文件。第8轮没有保存权重，无法从指标CSV恢复；新版从磁盘现有模型的验证Acc继续比较。

## 4. 阳性召回率、特异度、TP/TN/FP/FN

本项目中，阳性是标签 `1`，阴性是标签 `0`。以第 3 节历史输出为例：

| 真实类别 | 模型判阳性 | 模型判阴性 |
|---|---|---|
| 真实阳性 | TP=123：正确发现阳性 | FN=68：漏报阳性 |
| 真实阴性 | FP=428：误报为阳性 | TN=5230：正确识别阴性 |

`T/F` 表示判断对/错，`P/N` 表示模型预测阳性/阴性。四个数量相加应等于验证图片总数。

```text
阳性召回率 = TP / (TP+FN) = 123 / 191 ≈ 64.40%
特异度     = TN / (TN+FP) = 5230 / 5658 ≈ 92.44%
精确率     = TP / (TP+FP) = 123 / 551 ≈ 22.32%
```

这表示真实阳性中找出了 123 张、漏掉 68 张；真实阴性中正确识别 5230 张、误报 428 张。精确率目前未单独打印，上面的计算帮助理解 PR 指标。

不能只看召回率：全部判阳性会得到 100% 召回率，却把所有阴性都误报。因此要把召回率、特异度和误报数量结合起来看。

## 5. time 和 remaining 到底计的什么时间

| 出现位置 | `time` 的起点与范围 | `remaining` 估计的终点 |
|---|---|---|
| `epoch: ... batch: ...` | 当前这一轮训练开始后，包含取图、前向、反向及更新等耗时 | 当前这一轮训练结束，不包括后续验证或其余轮次 |
| 轮末 `epoch: ..., loss: ..., time:...s` | 刚完成的整轮训练耗时 | 此行不打印 remaining |
| `valid, batch: ...` | 当前这次验证开始后的图片处理和推理时间 | 当前这次验证结束 |
| `test, batch: ...` | 当前这次测试预测开始后的图片处理和推理时间 | 当前测试图片推理结束，不包括随后写 CSV 的时间 |

当前估算公式为：

```text
预计剩余秒数 = 已用秒数 ÷ 已完成批次数 × 剩余批次数
remaining显示值 = 预计剩余秒数 ÷ 60
```

`time:120.0s` 表示已用 120 秒，`remaining:2.0min` 表示预计还需 2 分钟。

首次读原图较慢，后续命中内存缓存可能加速；电脑负载、磁盘速度也会变化。因此预计剩余时间上下浮动是正常的，刚开始一批的估算尤其不稳定。`remaining:0.0min` 可能只是四舍五入接近零，是否结束还要看批次数及后续提示。

这些计时不包含程序最初导入库和建立数据集的全部耗时；验证/预测的计时也不包含此前模型加载。因此整次程序运行时间会比一条 `time` 更长。

## 6. 各种中文提示是什么意思

| 提示 | 当前在做什么、接下来会怎样 |
|---|---|
| `训练程序已启动, 正在加载PyTorch...` | 已经进入程序，正在导入库，还没有开始训练批次 |
| `正在读取glaucoma_first...` | 读取 CSV、匹配图片路径并建立数据集；图片随后按需读取 |
| `CPU线程:8` | PyTorch 使用设置的 8 个 CPU 计算线程，不表示 8 张显卡或 8 个图片加载进程 |
| `已加载现有参数, 先验证训练前模型...` | `RESUME=True` 且找到旧模型，先评估旧参数作为比较基准；此时尚未更新权重 |
| `开始训练 epoch: ...` | 开始该轮训练，接下来会更新模型参数 |
| `开始验证: 5849张有标签图片` | 当前轮训练完，或正在评估旧模型；在验证集上检查效果，不做反向传播 |
| `已保存最佳模型: ..., 验证Acc:...` | 完整验证集准确率严格提高，已保存最佳参数 |
| `本轮未超过最佳验证Acc:..., 保留最佳参数` | 验证准确率未提高，训练并非失败；之前参数仍保留 |
| `验证Acc停滞, 下一轮lr:...` | 学习率已减半；不改变本轮已经完成的训练，下一轮才使用新值 |
| `连续5轮未改善, 提前结束训练` | 正常早停，防止持续无效训练；不是程序崩溃 |
| `训练完成, 最佳验证Acc:...` | 达到上限或提前停止；显示保留模型的验证准确率，不一定是最后一轮 |
| `训练记录: ...` | 本次独立记录目录，位于项目文档/训练记录下 |
| `训练与验证结束...请单独运行predict.py` | `train.py` 正常结束；需要新答案时由用户自行运行预测文件 |
| `测试集没有真实标签...不计算准确率` | `test.csv` 没有真实答案，所以只输出预测和进度 |
| `已生成: ...共5855张图片, 预测阳性...张` | CSV 已写出；“预测阳性数”是模型的判断数量，不是真实阳性数或判对数量 |

续训只恢复权重，Adam和学习率调度器重新初始化，不是恢复全部中断现场。`epoch=0`按旧模型自己的结构和激活配置验证，没有对应训练loss/acc/lr。旧结构加宽时只迁移前三层卷积，其余重新初始化；相同宽五层续训恢复全部权重。

学习率调度也监控验证Acc：连续2轮未严格提高时减半，最低0.000001，改善阈值为0。连续5轮未提高则早停。判断使用未四舍五入的完整精度，不是终端显示的4位小数；AUROC和AUPRC只打印与记录，不参与保存、调度或早停。

## 7. 实际运行时如何判断是否有效

建议每轮结束按这个顺序观察：

1. 看验证 `Acc` 是否严格超过此前最佳值，决定本轮是否保存。
2. 看 `AUROC`、`AUPRC(梯形)`、`AP`，判断排序和阳性检出表现是否改善。
3. 看阳性召回率、`FN` 和 `FP`，理解漏报与误报的变化。
4. 看训练 `loss/acc` 的趋势，配合验证结果判断是否还值得继续训练。

| 现象 | 可能的解释 |
|---|---|
| loss 下降、训练 acc 上升，验证 AUROC 也上升 | 训练和验证都出现改善，是积极信号 |
| loss 继续下降、训练 acc 上升，验证 AUROC 反而下降 | 可能开始过拟合，也可能是训练波动；结合多轮验证趋势判断 |
| Acc 很高，但召回率接近 0 | 可能主要依靠预测多数阴性类取得高准确率 |
| Acc 降低，但 AUROC 或召回率改善 | 排序能力或阳性检出可能更好，同时阈值下的误报增加；不必仅凭 Acc 判断变差 |
| 本轮没有保存模型 | 验证Acc没有严格提高，程序按当前选择规则保留旧模型；不代表所有指标都更差 |

训练 loss 并不是验证 loss，当前终端没有输出验证损失；不要把两者混在一起比较。

所有本地验证指标只代表这份验证集上的表现。测试集有自己的分布和未公开标签，平台分数不等于本地 `Acc×100`，也不能看到“50分”就认为图片只判对了一半。

## 8. 输出记录在哪、说明对应哪些代码

| 文件 | 保存或实现的内容 |
|---|---|
| `项目文档/训练记录/时间目录/training_history.csv` | 本次完成轮次、验证指标、该轮和下一轮学习率；不同运行互不覆盖 |
| `项目文档/训练记录/时间目录/run_config.json` | 本次超参数、实际完成轮数，以及候选配置和保留模型配置 |
| `submission/model/config.json` | 当前保留模型的最佳轮次和验证指标 |
| `submission/model/best_model.pth` | 最佳权重；新版同时保存实际激活和失活配置 |
| `submission/results/submission.csv` | 单独运行 `predict.py` 生成的提交答案，训练不会自动更新它 |

`training_history.csv` 中的 `train_loss/train_accuracy` 对应终端 `loss/acc`，`accuracy` 对应 `Acc`，`auroc/auprc/ap` 对应三个验证排序指标，`recall/specificity` 对应召回率和特异度。

`learning_rate` 是该轮实际使用值，`next_learning_rate` 是调度后的值；如果已经早停，后者不会再使用。`best_epoch_this_run=0` 表示未超过旧模型，旧模型及其配置不变。本版不自动保存完整终端文字，只保存结构化训练记录。

本项目实现位置：

- [train.py](../submission/code/train.py)：训练 loss/acc、轮次、每轮验证及最佳参数选择。
- [predict.py](../submission/code/predict.py)：验证结果、测试预测和生成 CSV 的提示。
- [utils.py](../submission/code/utils.py)：`print_progress()` 计算时间和进度；`calculate_metrics()` 计算验证指标；`save_training_record()` 保存历史。

本文中的历史数值仅为解释示例。运行时以你这一次终端输出和对应记录文件为准。
