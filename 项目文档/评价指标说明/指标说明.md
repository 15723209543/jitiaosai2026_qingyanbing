先给你一句最重要的解释：

**准确率看“最终判对了多少张”；AUROC看“模型能不能把真正的阳性图片，排在阴性图片前面”。**

两者评价的不是同一件事。下面从你自己的训练结果开始讲，把公式和例子都写清楚。

## 一、模型首先输出的是“分数”，然后才变成“阳性/阴性”

对于一张图片，模型会输出一个阳性概率，例如：

```
图片A：0.90
图片B：0.60
图片C：0.40
图片D：0.10
```

你可以先把它理解成：

> 分数越高，模型越认为这张图片像阳性。

注意，这是模型给出的概率估计，不代表它已经经过验证、能精确反映实际患病概率。

当前代码设置的判定阈值是 **0.5**：

\[ \hat y= \begin{cases} 1，即阳性 & p\geq 0.5\\ 0，即阴性 & p<0.5 \end{cases} \]

其中：

- \(p\)：模型给出的阳性概率。
- \(\hat y\)：模型最终预测的类别。
- \(y\)：数据集提供的真实类别。

所以，**概率分数和最终分类结果，是两个不同的东西。**

准确率主要使用最终分类结果；AUROC使用原始概率分数。

## 二、先理解四个基础数字：TP、TN、FP、FN

你原有模型的验证结果是：

```
TP:125  TN:5286  FP:372  FN:66
```

把它们放进表格就容易理解了：

| 实际情况 | 模型判断阳性            | 模型判断阴性             |
| -------- | ----------------------- | ------------------------ |
| 实际阳性 | TP＝125：正确找出的阳性 | FN＝66：漏掉的阳性       |
| 实际阴性 | FP＝372：误报的阴性     | TN＝5286：正确排除的阴性 |

记住：

- **TP：真阳性**——实际阳性，也判断为阳性。
- **TN：真阴性**——实际阴性，也判断为阴性。
- **FP：假阳性**——实际阴性，却误报为阳性。
- **FN：假阴性**——实际阳性，却漏判成阴性。

因此：

\[ 实际阳性总数=TP+FN=125+66=191 \]\[ 实际阴性总数=TN+FP=5286+372=5658 \]\[ 图片总数=TP+TN+FP+FN=5849 \]

后面的大部分指标，都由这四个数字计算。

## 三、准确率、召回率、精确率、特异度分别是什么？

### 1. 准确率：所有图片中，总共判对了多少？

英文是 Accuracy，终端里的 `Acc` 就是它。

\[ Accuracy=\frac{TP+TN}{TP+TN+FP+FN} \]

代入你的数字：

\[ Accuracy=\frac{125+5286}{5849} =\frac{5411}{5849} \approx92.51\% \]

意思是：

> 5849张验证图片中，有5411张判断正确。

但准确率有一个明显问题：**容易被数量特别多的类别影响。**

你的验证集有5658张阴性。如果模型不看图片，全部回答“阴性”：

\[ Accuracy=\frac{5658}{5849}\approx96.73\% \]

准确率比你现在还高，但191张阳性一张都没找到。

因此，**准确率高，不一定代表阳性识别能力强。**

### 2. 召回率：真正的阳性中，找出来多少？

英文是 Recall，也叫敏感度、Sensitivity、真正率TPR。

\[ Recall=\frac{TP}{TP+FN} \]

代入你的结果：

\[ Recall=\frac{125}{125+66} =\frac{125}{191} \approx65.45\% \]

意思是：

> 实际191张阳性，模型找到了125张，找出了约65.45%。

与它相对应的是漏报率：

\[ 漏报率=\frac{FN}{TP+FN}=1-Recall \]\[ 漏报率=\frac{66}{191}\approx34.55\% \]

**召回率主要回答：“真正有问题的图片，我漏掉了多少？”**

### 3. 精确率：被模型说成阳性的图片，有多少真的阳性？

英文是 Precision，也叫查准率。

\[ Precision=\frac{TP}{TP+FP} \]

代入你的数字：

\[ Precision=\frac{125}{125+372} =\frac{125}{497} \approx25.15\% \]

意思是：

> 模型一共把497张图片判为阳性，但其中真正阳性的只有125张。

它与召回率最容易混淆：

- **召回率的分母：实际阳性总数。**
- **精确率的分母：模型预测阳性总数。**

可以这样记：

> 召回率：真的阳性，我找全了吗？
> 精确率：我找出来的这些，真的准吗？

两者的标准定义分别是 \(TP/(TP+FN)\) 和 \(TP/(TP+FP)\)。[官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_curve.html)

### 4. 特异度：真正的阴性中，正确排除了多少？

英文是 Specificity，也叫真负率TNR。

\[ Specificity=\frac{TN}{TN+FP} \]

代入你的数字：

\[ Specificity=\frac{5286}{5286+372} =\frac{5286}{5658} \approx93.43\% \]

意思是：

> 实际5658张阴性，模型正确排除了5286张。

与它相对应的是假阳性率FPR：

\[ FPR=\frac{FP}{TN+FP}=1-Specificity \]\[ FPR=\frac{372}{5658}\approx6.57\% \]

意思是：

> 所有实际阴性中，有6.57%被误报成了阳性。

**注意：FPR不是 \(1-Precision\)，因为两者分母不同。**

## 四、重点：AUROC究竟是什么意思？

### 1. 先用“排序”理解它

假设只有4张图片：

| 图片 | 真实类别 | 模型给出的阳性概率 |
| ---- | -------- | ------------------ |
| A    | 阳性     | 0.90               |
| B    | 阴性     | 0.80               |
| C    | 阳性     | 0.40               |
| D    | 阴性     | 0.10               |

理想情况下，模型应该给阳性更高的分数，即把A、C都排在B、D前面。

但这里B是阴性，却得到了0.80，比阳性C的0.40还高，说明有一部分排序错误。

现在把“每张阳性”和“每张阴性”分别比较：

| 比较                     | 阳性分数是否更高？ |
| ------------------------ | ------------------ |
| 阳性A 0.90 对 阴性B 0.80 | 是                 |
| 阳性A 0.90 对 阴性D 0.10 | 是                 |
| 阳性C 0.40 对 阴性B 0.80 | 否                 |
| 阳性C 0.40 对 阴性D 0.10 | 是                 |

共比较4对，其中3对排对了：

\[ AUROC=\frac{3}{4}=0.75 \]

**这就是AUROC最直观的理解：随机拿一张阳性和一张阴性，模型把阳性排在前面的能力。**

如果两张图片分数相同，按半次正确计算。对于当前普通二分类、未加权的情况：

\[ AUROC= \frac{ 阳性分数更高的配对数 +0.5\times分数相同的配对数 }{ 阳性图片数\times阴性图片数 } \]

所以：

- **AUROC＝1**：这份数据上，每张阳性都排在每张阴性前面。
- **AUROC约等于0.5**：排序能力接近随机。
- **AUROC低于0.5**：排序方向比随机还差，需要检查模型或概率、标签方向。

你的 `AUROC=0.898348` 描述的是这种排序表现，**不是“89.83%的图片分类正确”**。代码计算时输入的是真实标签与连续阳性分数。[AUROC官方接口说明](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html)

### 2. 为什么名称里有“曲线下面积”？

AUROC全称是：

> Area Under the Receiver Operating Characteristic Curve
> ROC曲线下面积

ROC曲线是这样画出来的：

- 横轴：假阳性率 \(FPR\)，也就是阴性被误报的比例。
- 纵轴：真正率 \(TPR\)，也就是阳性召回率。
- 不断改变判定阈值，每个阈值对应一个点。[ROC官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_curve.html)

还是刚才的4张图片：

| 阈值 \(t\)，分数≥t判阳性 | 判阳性的图片 | FPR  | TPR/召回率 |
| ------------------------ | ------------ | ---- | ---------- |
| 大于0.90                 | 无           | 0    | 0          |
| 0.90                     | A            | 0    | 0.5        |
| 0.80                     | A、B         | 0.5  | 0.5        |
| 0.40                     | A、B、C      | 0.5  | 1          |
| 0.10                     | 全部         | 1    | 1          |

把这些点依次连起来，就是ROC曲线。

这条曲线下面的面积为：

\[ AUROC=0.5\times0.5+0.5\times1=0.75 \]

和刚才“4对中排对3对”的结果一样。

一般情况下，程序可以按梯形面积累加：

\[ AUROC= \sum_{i=1}^{m} (FPR_i-FPR_{i-1}) \frac{TPR_i+TPR_{i-1}}{2} \]

其中每一项就是：

\[ 梯形面积=宽度\times两边高度的平均值 \]

**“排序正确的比例”和“ROC曲线下面积”，是理解同一个指标的两种方式。**

### 3. 为什么AUROC提高，准确率却可能下降？

因为：

- 准确率只看当前一个阈值，例如0.5。
- AUROC综合考虑不同阈值下的排序表现，不只看0.5。

用刚才的例子：

当阈值为0.5时：

- A阳性：判对。
- B阴性：误报。
- C阳性：漏报。
- D阴性：判对。

因此：

\[ Accuracy=\frac{2}{4}=50\% \]

但：

\[ AUROC=0.75 \]

如果只把判定阈值改为0.3：

- A、C都被正确识别为阳性。
- B仍然误报。
- D仍然正确。

于是：

\[ Accuracy=\frac{3}{4}=75\% \]

但概率分数和排序没变：

\[ AUROC仍然=0.75 \]

**这说明准确率与AUROC不是同一个指标，不能相互直接换算。**

另外，只知道一个阈值下的TP、TN、FP、FN，**不能反推出AUROC**。计算AUROC需要每张图片的真实标签和概率分数。

## 五、AUPRC和AP又是什么？

它们都围绕刚才讲过的两个指标：

- Precision：找出来的阳性，准不准？
- Recall：真正的阳性，找得全不全？

### 1. AUPRC：不同阈值下，“准”和“全”的综合表现

不断改变阈值，计算对应的Precision和Recall：

- 横轴：Recall。
- 纵轴：Precision。

画出的曲线叫PR曲线，下面的面积叫AUPRC。

当前项目使用的是**梯形积分**。按召回率从小到大的顺序排列曲线点：

\[ AUPRC_{\text{梯形}}= \sum_{i=1}^{m} (R_i-R_{i-1}) \frac{P_i+P_{i-1}}{2} \]

其中：

- \(R_i\)：第i个点的召回率。
- \(P_i\)：第i个点的精确率。

它不是“总体判对的比例”，也不是某一个阈值下的Precision。

你的：

```
AUPRC(梯形): 0.417890
```

不表示“41.79%的图片判对”，而是PR曲线面积约为0.4179。

它特别适合补充观察这种阳性很少的任务，因为误报会直接拉低Precision。不过，**阳性比例变化也会影响它，比较时应使用同一份验证集。**

### 2. AP：另一种汇总PR曲线的方法

AP是Average Precision，平均精度。

公式是：

\[ AP=\sum_{i=1}^{m}(R_i-R_{i-1})P_i \]

直观解释：

> 每多找出一部分阳性，就用当时的精确率给这一部分表现计分。

还是刚才4张图片，按分数从高到低查看：

1. 首先选中A：找到了1/2的阳性，召回率增加0.5，精确率为1。
2. 再选中B：没有新增真阳性，召回率没有增加。
3. 再选中C：找齐全部阳性，召回率再增加0.5，此时精确率为2/3。
4. 再选中D：召回率不再增加。

所以：

\[ AP=0.5\times1+0.5\times\frac{2}{3} =\frac{5}{6} \approx0.8333 \]

AP与梯形AUPRC的区别：

- AUPRC梯形法使用相邻两个点精确率的平均值。
- AP使用每次召回率增加时对应的精确率。
- **计算方法不同，数值不必相等。**[AP公式与区别](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)

因此，你终端里同时打印：

```
AUPRC(梯形): 0.417890
AP: 0.421611
```

不是程序计算矛盾，而是在报告两种不同的汇总方法。

## 七、loss、acc以及其他终端字段

### loss：训练时用来惩罚预测错误的数值

你当前使用交叉熵损失。

对于一张图片，设真实标签 \(y\in\{0,1\}\)，预测阳性概率为 \(p\)：

\[ Loss=-[y\ln p+(1-y)\ln(1-p)] \]

分开看就简单了。

真实是阳性，即 \(y=1\)：

\[ Loss=-\ln p \]

真实是阴性，即 \(y=0\)：

\[ Loss=-\ln(1-p) \]

例如，一张真实阳性图片：

| 模型给出的阳性概率 | 损失                    |
| ------------------ | ----------------------- |
| 0.9                | \(-\ln0.9\approx0.105\) |
| 0.5                | \(-\ln0.5\approx0.693\) |
| 0.1                | \(-\ln0.1\approx2.303\) |

**越自信地判断错误，受到的惩罚越大。**

一批样本的平均损失是：

\[ 平均Loss=\frac{1}{N}\sum_{i=1}^{N}Loss_i \]

当前终端打印的是本轮已处理训练样本的累计平均交叉熵。`loss=0.2`不代表错误率20%，`1-loss`也不等于准确率。

### acc和Acc：只是本项目的大小写约定

- `acc`：训练期间，当前轮已处理样本的准确率。
- `Acc`：完整验证集的准确率。

训练时启用了随机抽样、翻转和Dropout，并且权重不断变化；验证时模型固定、关闭随机失活。因此两者不能简单比较大小后就断定是否过拟合。

### 其他字段

| 字段        | 含义                             |
| ----------- | -------------------------------- |
| `epoch`     | 训练轮次                         |
| `batch`     | 一轮中的第几批图片               |
| `lr`        | 学习率，控制参数每次调整的步长   |
| `time`      | 当前训练轮或验证阶段已经用了多久 |
| `remaining` | 根据当前速度估算，本阶段还剩多久 |

预计剩余时间的基本公式是：

\[ 预计剩余时间= \frac{已用时间}{已完成批次数} \times剩余批次数 \]

它不是准确预报，也不包含后面所有训练轮次。

## 最后，用六句话记住

- **准确率Acc：所有图片，总共判对多少？**
- **召回率Recall：真正的阳性，找出来多少？**
- **精确率Precision：我判为阳性的，多少真是阳性？**
- **特异度Specificity：真正的阴性，正确排除多少？**
- **AUROC：阳性的分数，能否总体排在阴性前面？**
- **AUPRC/AP：在不同阈值下，找阳性能否既找得全，又报得准？**

**其中最关键的区别是：准确率评价一个阈值下的最终分类；AUROC评价概率分数的排序能力。**
