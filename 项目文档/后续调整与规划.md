# 后续调整与规划（v1.2.0）

更新日期：2026-10-15。助手只修改代码和轻量检查，不执行正式训练或整批预测。

## 1. 起点：保留79分版本

用户反馈当前平台成绩为79分。仓库基线为 `v1.1.1 / 7597303`，平台分数不等于准确率。
修改前本地最佳验证：AUROC 0.893341、梯形AUPRC 0.394133、AP 0.396894、召回率79.58%。
本次5轮记录中训练acc由89.54%升至94.67%，验证最佳仍在第1轮，有过拟合迹象，不能仅靠继续增大神经元解决。

旧模型、配置、CSV及训练历史保留于 `训练记录/20261014_v1.1.1_79分基线/`。10月15日继续任务时，工作区已有 `训练记录/20261014_201900_433112/` 的3轮训练记录及更新后的正式模型；助手保留这些现有产物，不重新训练或回退。答案CSV尚未更新。

这份现有记录中第2轮最佳验证 AUROC 为0.896657、梯形AUPRC为0.407388、召回率为67.02%。与旧基线相比排序指标略升，但0.5阈值下召回率下降；不能仅据此认定平台分数提高。记录停在第3轮，不等于已完成12轮，也不能据此确定停止原因。

## 2. 已实施、由用户运行的方案

- 保持64×64输入、三组卷积和两个2048神经元全连接层，继续迁移现有权重。
- 中间激活改为LeakyReLU(0.01)，输出层仍输出两类logits。
- 第三组卷积/池化后增加Dropout2d(0.1)，保留全连接Dropout(0.5)；验证和预测关闭失活。
- 保留Adam，初始学习率5e-5，L2权重衰减1e-4。
- 验证AUROC连续2轮没有超过调度器记录值至少1e-4时，学习率减半，最低1e-6。
- 最多12轮，连续5轮未超过最佳模型提前停止。最佳模型优先AUROC，相同时比较梯形AUPRC。
- 保留均衡采样、普通交叉熵、训练水平翻转和内存缓存，不新增外部数据或复杂框架。

这些是待验证的超参数选择，不是已证明提分的结论。本轮同时改变多项设置，若有效，不能把提升单独归因于某一项。

## 3. 下一步操作

1. 选择jitiaosai解释器，运行submission/code/train.py。
2. 确认首先打印旧模型验证结果，这是本次比较基准。
3. 查看每轮AUROC、梯形AUPRC、AP和召回率，不用训练acc代替验证效果。
4. 提前停止是正常控制流程，不是报错。
5. 打开终端打印的训练记录时间目录，检查实际轮数和学习率变化。
6. 需要新答案时单独运行predict.py，检查5855行后上传CSV。
7. 把平台成绩与运行时间、代码提交号记录在一起。验证改善而平台下降时保留旧基线，检查泛化，不连续试探测试标签。

## 4. 训练记录

每次运行创建精确到微秒的独立时间目录：

- training_history.csv：epoch、loss/acc、验证指标、该轮及下一轮学习率。
- run_config.json：超参数、实际完成轮数、最佳轮次、最佳模型配置和候选训练配置。

epoch=0是旧配置的基准验证，没有训练loss/acc。best_epoch_this_run=0时，原pth和model/config.json不变，但本次记录仍保存。预测从pth获取配置；旧纯权重自动按ReLU版本解释。
每轮及时记录已完成结果，不自动保存完整终端文字、优化器状态或每轮权重副本。

## 5. 后续实验一次改一个因素

| 顺序 | 因素 | 对比方法与风险 |
|---|---|---|
| A | 本版与79分旧版 | 先完成真实训练，轻量检查不能当作成绩 |
| B | 激活函数 | 同一起始权重下比较negative_slope为0与0.01 |
| C | 卷积失活 | 比较conv_dropout为0、0.05、0.1，避免过强导致欠拟合 |
| D | 学习率 | 比较3e-5与5e-5，同时记录衰减次数 |
| E | 提高图片分辨率 | 本版不做；需同步全连接输入或池化，另行确认 |
| F | 增加卷积通道 | 本版不做；参数形状改变，需要重考虑权重迁移 |

当前总参数约1373万，大部分在全连接层。先解决验证停滞，再考虑扩容。只能使用主办方数据，不加入外部标注数据，不用无标签测试集代替验证集。

## 6. 回退方法

程序停止时，把基线目录中的best_model.pth、config.json复制回submission/model，把基线submission.csv复制回submission/results。
回退前保存新实验，避免丢失参数。新代码兼容旧纯权重，会恢复ReLU推理。
完整旧训练算法在Git提交7597303中；只恢复权重不会把下一次训练默认设置改回旧版。

## 7. Git与运行边界

每次任务先获取远端状态，不一致先安全同步，不能覆盖未保存训练结果。提交格式为 `版本号 类型(影响范围):行为`。
原始数据和.idea不提交，其余有用文件提交。results只放提交答案。
正式性能、平台分数以及T4上的单张延迟仍需用户后续运行确认。
