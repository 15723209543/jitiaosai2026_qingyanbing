# 后续调整与规划（V1.3.2）

日期：2026-10-15。助手只修改代码和做轻量检查，不训练，正式预测也由用户执行。

## 1. 本次修改

保持五层卷积32→64→128→256→512、池化、激活、Dropout及其他超参数不变。完整验证集AUROC优先；AUROC完全相同时，AUPRC更高才保存，两项都相同保留旧模型。准确率和AP不参与保存判断。比较完整数值，不比较终端四舍五入结果。

学习率和早停观察本次候选模型自身的验证AUROC，不以旧冠军为进步门槛。首轮建立自身基准；随后连续2轮未超过自身最高值则学习率减半，连续10轮未提高则早停。最多12轮，初始学习率5e-5，最低1e-6，weight_decay=1e-4，batch64。

## 2. 为什么不继续加层

用户记录20261015_153819_312440中，宽五层第4轮AUROC=0.918078、AUPRC=0.436519，高于原模型0.898348和0.417890；但Acc=91.84%低于原模型92.51%，被上一版准确率规则排除。已有改善迹象，先修正选模规则，不继续加层。未保存的第4轮权重无法从CSV恢复，需由用户重新训练。

规程第4—5页按AUROC排名，相同才按AUPRC二次排序。本地AUPRC沿用梯形积分，AP不是同一个算法；官方未公布积分实现。验证集全部猜阴性也能达到约96.73%Acc，不能只看准确率。

## 3. 用户操作

1. 用jitiaosai运行submission/code/train.py，先验证旧模型，再训练和每轮验证。
2. 查看AUROC、AUPRC、召回率和耗时。正式冠军仍需超过旧模型；候选自身进步即可避免停滞计数，不要求每轮成为冠军。
3. 到项目文档/训练记录/时间目录查看training_history.csv和run_config.json。新版selection_metric=validation_auroc，tie_break_metric=validation_auprc。
4. 训练完单独运行predict.py生成submission/results/submission.csv，再上传CSV；train不会更新答案。
5. 记录官网分数，由用户维护版本前两位；本地指标不能直接换算为官网分数。

## 4. 后续实验与保存边界

先跑当前版本，避免同时改模型和超参数。若训练acc提高但验证AUROC持续下降，再单独比较正则强度或学习率；若两者都低，再比较容量或分辨率。使用同一验证集，每次只改一个主要因素。

本版没有新增last_checkpoint.pth或完整断点框架，仍只保存最佳权重。RESUME只恢复权重，Adam/调度器重新初始化。未胜出轮次的权重不能从CSV恢复；每轮续训断点作为后续可选功能，不让predict自动读取非最佳参数。

模型约60.83MB，小于500MB；单张端到端延迟≤100ms仍需在推荐环境实测，不以文件大小推断速度。

旧79分基线在训练记录/20261014_v1.1.1_79分基线，历史实验由Git保留。回退前停止程序并保留新实验，再恢复匹配的模型与配置。
