# 后续调整与规划（v1.4.3）

日期：2026-10-16。已按用户授权落实方案B1，训练由用户执行。

## 1. 当前实验

五层卷积、64×64输入和采样方式不变；全连接缩为4608→512→2。已训练卷积学习率1e-5，分类头1e-4，保留Adam/L2=1e-4、LeakyReLU(0.01)、卷积失活0.1、分类失活0.5。梯度范数上限5用于异常保护。

本地仅以验证AUROC严格提高更新正式模型；相等不比较ACC或AUPRC。学习率调度和早停也看候选自身AUROC，最多12轮、停滞5轮早停，不继续单纯增加轮数。

目前输入和batch都保留为64，不代表它们已经是最优；这样可以先观察精简模型的效果。

## 2. 用户操作

1. 确认起始权重。默认读取当前磁盘模型（今日ACC冠军）。昨日AUROC权重/配置在Git提交97618d6，需要时先备份再成对恢复；助手本次未自动回滚。
2. 用jitiaosai运行train.py，查看每批进度以及每轮完整验证AUROC。
3. 到项目文档/训练记录/本次时间目录查看记录和候选best_model.pth。候选文件自带其epoch、validation；run_config.json中的validation属于正式冠军。
4. 候选严格胜出才会更新submission/model/best_model.pth；训练结束不会自动生成CSV。
5. 手动运行predict.py生成答案，官网只提交CSV；记录对应版本、pth、官网分数，不把训练Acc当作提交成绩。

## 3. 下一步只做有依据的对照

- 若B1验证AUROC提高且没有明显速度退化，单独尝试96×96输入，更新权重尺寸元数据并重新测速；暂不叠加更多池化。
- 若训练指标提高、验证AUROC持续下降，优先对照温和旋转/亮度增强，或阳性采样比例50%与25%，一次只改一个方向。
- 若训练和验证都较差，先检查新分类头是否学会，再考虑学习率/容量。不能仅看到训练Acc低就加层。
- 激活函数替换、BatchNorm、残差结构、额外加权损失留作后续实验；现有证据不支持一次全部更换。
- 对最有希望的方案补一次不同随机种子的重复实验。只有191个验证阳性，微小涨幅可能是波动，不凭一次上升承诺线上提分。

## 4. 保留与验收边界

正式冠军与每次候选最佳分开；候选可以进步却暂未超过冠军。当前不保存Adam状态或每轮完整快照，未保留的中间权重仍不能从指标CSV恢复。

新结构参数约15.72MB，实际保存文件含少量元数据；总模型大小须≤500MB。单张端到端≤100ms要实测，不能用平均批量吞吐冒充单张延迟。改变输入尺寸、集成多个模型后必须重测。

原始数据不提交；不使用外部标注图片或外部预训练权重。本版不改解释器。提交前先验证代码/兼容性，正式训练与官网评分留给用户。
