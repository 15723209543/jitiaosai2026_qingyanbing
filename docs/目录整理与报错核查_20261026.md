老师截图中旧代码在 `torch.load` 处报 `Unsupported operand 118`。旧 `submission/model/best_model.pth` 在本机只有 133 字节，其首行是 `version https://git-lfs.github.com/spec/v1`，并非 PyTorch 权重；首字母 `v` 的 ASCII 码正是 118。前次修复的 `TorchVersion` 安全名单解决的是另一个报错，不能把文本指针变成权重。新 `submission/code/utils.py` 在调用 `torch.load` 之前明确识别并拒绝 Git LFS 指针，给出下载真实权重的提示。`predict.py`、`train.py` 均走同一读取入口。

本机通过 Git LFS 取回并核对新目录阶段性权重：200,822,431 字节，SHA-256 `cc5aa8c36f195c7e014659e832932ad596deaf506a7e57ad7c9e7337cf8ae6bb`。安全加载后其两个分支的历史最佳记录为 ConvNeXt-Tiny 第 6 轮 AUROC 0.984011、EfficientNetV2-S 第 3 轮 AUROC 0.965275；但 `training_complete=False`、`selection=None`。因此没有运行候选预测，也没有用旧 CSV 假充候选输出。用户需在 GPU 机续训并完成最终方案选择，再运行 `submission/code/predict.py` 写新 CSV。
