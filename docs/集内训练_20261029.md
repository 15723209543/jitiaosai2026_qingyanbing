# submission3 集内训练记录 2026-10-29

## 1. 任务与口径

按用户要求，把 `submission3`（官方 `train+valid` 合并后既训练又评估）跑一轮并生成提交 CSV，用于观察"把 valid 并入训练"这条路在平台上的真实效果。

**口径提醒（最重要）**：`train.py` 把 `glaucoma_first/train` 与 `valid` 合并成 57,245 张（阳 1,848 / 阴 55,397），同一批图既训练又用于"训练集内 AUROC"选模。因此：

- 该 AUROC **不是验证指标**，同图记忆会随轮次单调推高它，选模实际上等于"取最后一轮"；
- 不能与 `submission/` 的官方验证 AUROC 0.985969 横向比较；
- 本轮唯一可信的判据是**赛方平台测试分数**，参照 97.82（历史最好）与 97.22（2026-10-28 晋升后）。

## 2. 本轮配置（与原配置的差异）

只动"跑几轮、几个加载进程"，**预处理、损失、学习率、batch、推理一律不变**：

| 项 | 原值 | 本轮 | 说明 |
| --- | --- | --- | --- |
| `epochs` | 1 | **1** | 数值未变。运行环境是 8 GB 显存 / 16 GB 内存笔记本，实测 1 轮训练 + 1 轮全量集内验证约 15 分钟，且提交内存有上限，故两支各跑 1 轮 |
| `patience` | 3 | **3** | 未变 |
| `backbone_lr` / `head_lr` | 2e-5/2e-4、3e-5/3e-4 | **不变** | 暖启动权重已收敛，本轮目标是吸收 5,849 张新增标注，不是重学特征 |
| `NUM_WORKERS` | 4 | **6** | 本机加载是瓶颈，按实测调整 |
| `persistent_workers` | True | **False** | 本机提交内存限制 |

两项加载相关改动都是**本机资源适配**，内存充裕的机器可以直接还原，不影响训练数学（见第 5 节还原清单）。

## 3. 逐轮集内 AUROC（**不是验证指标**）

| 分支 | 开训前基线（合并集内） | 第 1 轮 | 是否保存 | 该分支官方 valid |
| --- | --- | --- | --- | --- |
| convnext_tiny.fb_in1k | 0.997001 | 0.998374 | 是 | 0.984011 |
| efficientnetv2_rw_s.ra2_in1k | 0.996459 | 0.999449 | 是 | 0.961078 |

最终选模（同样只看集内）：ConvNeXt 0.998374、EffNet 0.999449、**等权组合 0.999855 → 选 ensemble**。

**这两组数字必须这样读**：EffNet 官方验证只有 0.9611，一进合并集内就 0.9965，训练一轮后 0.9994 —— 涨的是"它已经见过这张图"，不是"它更会看病"。基线 0.997001 与 0.996459 是同一个权重的两个不同口径，差距纯粹来自训练／评估同图。因此本轮不宣称任何泛化提升。

## 5. 本轮对 `submission3/code` 的改动

**BUG-1（任何机器都会踩，必须保留）**：`utils.py` 的 `BASE_RECIPE` 原写 `imagenet1k_convnext_efficientv2_rgb384_fullframe_v1`，而正式 `submission/model/best_model.pth` 内的实际配方是 `..._balanced_pairauc_v4_official_only_20261028`（2026-10-28 晋升时改过）。原代码在 `load_resume_checkpoint(BASELINE_MODEL_PATH, ...)` 处直接抛"已有模型配方与当前代码不一致"，**暖启动必然失败，等于无法从正式权重续训**。已改为实际字符串；只影响"识别哪份权重算正式基线"，`RECIPE` 与训练数学均未动。

**本机适配（可还原，不影响训练数学）**：

```python
# utils.py
NUM_WORKERS = 4                                   # 还原：原值 4（或按你的机器实测）

# train.py  loader()
persistent_workers=NUM_WORKERS > 0                # 还原：原值（本机为避开提交内存上限改成了 False）
# CONFIG 的 epochs=1 / patience=3 / 学习率本来就是原值，无需改动
```

本机适配只针对"这台 8 GB 显存 / 16 GB 内存 / 10 GB 页面文件 的笔记本"；换机器跑请按第 5 节还原清单处理，README 与模型文件不必改动。

## 6. 平台分数

**待提交后回填。** 判据顺序：先与 97.82（历史最好）比，其次与 97.22（2026-10-28 晋升后）比。

- 若高于 97.82：说明把 valid 并入训练确实带来收益，可考虑在此方向上增加轮数。
- 若低于 97.22：说明这条路在本赛题上不成立，应回到"只用官方 train 训练 + valid 选模"的路线。
- 历史最好的 CSV 可从 commit `0529aae` 复原，本机另存于 `runs/fallback_97.82/submission_97.82.csv`。
