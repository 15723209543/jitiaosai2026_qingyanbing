用户要求并行保留两个独立实验，均不改正式 `submission/` 的模型、CSV 与源码。

## submission2：只调整优化参数

从 v1.15.5 的 v3 配方参数继续：ConvNeXt-Tiny 的主干/分类头学习率设为 `1.5e-5/1.5e-4`，EfficientNetV2-S 为 `2e-5/2e-4`，训练期分类头 Dropout 从 0.1 降到 0.05，两者最多各 30 轮、连续 10 轮无官方验证 AUROC 提升早停。已有 2.0 梯度裁剪、采样、focal+0.1 倍成对 AUC 损失、384 整图补边和 train→额外数据→官方 valid 的顺序不变。新配方标识 v4，可只读载入 v2/v3 候选或正式版旧权重；新参数仅写 `submission2/model/`。对照时应只比相同官方验证集、相同数据和实际训练轮数，不承诺提升。

## submission3：按用户明确指定的训练集内实验

从正式 `submission/code` 四文件与 `cost.py` 复制，不复制已有 PTH/CSV。官方 `glaucoma_first/train.csv` 与 `valid.csv` 合并后，每张图片既参加本轮训练，也参加无增强的“训练集内 AUROC”计算。训练开始可从正式 `submission/model/best_model.pth` 只读暖启动，若新候选 `submission3/model/best_model.pth` 已存在则优先继续它；两个骨干分别按训练集内 AUROC 严格提高保存，最终单模型/双模型仍由训练集内 AUROC 选择，写一个 PTH。`predict.py` 仅在用户单独运行时读取官方 `test.csv` 写三列 `submission3/submission.csv`，不使用 test 调参数。原始预训练权重需训练机可访问 Hugging Face，或已有真实正式 PTH；本机正式 PTH 只是 Git LFS 指针，不能在本机执行完整训练。

**警告：submission3 的 AUROC 存在训练／评价同图的数据泄漏，不是独立验证成绩，不能与 submission2 的官方验证 AUROC 直接比较，也不能据此声称模型泛化提升。** 用户明确要求尝试，故代码保留，但终端和 PTH 选择字段均标为 `insample`。该实验不替换正式模型或结果，只有额外的真正独立评估才能判断收益。

研究依据：[ICCV 2021 深度 AUC 最大化](https://openaccess.thecvf.com/content/ICCV2021/html/Yuan_Large-Scale_Robust_Deep_AUC_Maximization_A_New_Surrogate_Loss_and_ICCV_2021_paper.html)采用无泄漏验证来评估；[LibAUC 的 DualSampler 建议](https://docs.libauc.org/api/libauc.sampler.html)说明当前正例每批 1/16（6.25%）相对原始约 3% 并非异常，所以本轮不同时改采样和 AUC 损失。以上论文不保证本题达到某个 AUROC。
