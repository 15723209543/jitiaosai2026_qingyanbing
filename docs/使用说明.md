## 2026-10-27 submission2 额外数据追加训练（代码已测试，待真实训练）

额外数据训练**默认启用**：`train.py` 中 `MY_DATA_ENABLED = False` 是关闭值，紧接着的 `MY_DATA_ENABLED = True` 是启用行；只注释启用行就会关闭。每一轮的额外训练代码与上下各用五个空行隔开；终端在每轮两个训练段开始时打印数据集名称，每 25 批进度也带来源名。

`submission2/code/train.py` 对每个模型的**每一轮**都先用完整官方 `glaucoma_first/train` 训练一次，再用同级 `glaucoma_first_my/train`、`valid`、`test` 的全部图片追加训练一次，之后只用官方 `glaucoma_first/valid` 验证一次，并按该模型的历史最佳 AUROC 决定是否保存。两段训练共用当轮的模型和优化器；额外目录的 `valid/test` 只是其原始文件夹名，不作验证或预测。TXT 第一项 `0` 映射分类阳性 `1`，`1` 映射阴性 `0`，后续定位坐标不参与分类。原始数据保持独立目录且不写回；每轮次数仍由各模型 `CONFIG` 的 `epochs` 决定。`train.py` 不生成 CSV，`predict.py` 仍只读官方测试集。

此处只完成代码及合成数据单批测试，没有启动完整训练；新增数据的真实训练效果、最终合规性和官方成绩尚未验证。原始额外数据不随代码提交；用户表示组委会允许使用，许可原文仍需在最终参赛使用前核对。

## 2026-10-27 submission2 均衡采样与 AUC 损失实验

`submission/` 保留用户已提交的 97.82 分版本；新 `submission2/` 是独立实验，不能把两个目录的 PTH/CSV 混用。它读取同级 `glaucoma_first/train.csv` 和 `valid.csv`，仅前者参与训练。训练前先检查 GPU 训练机的 `submission/model/best_model.pth` 是真实权重而非 134 字节 Git LFS 指针；若 `submission2/model/best_model.pth` 尚不存在，训练脚本只读旧权重暖启动，先在全部官方验证集复核，再从本次第 1 轮训练。新候选存在时优先从候选继续，旧权重始终不覆盖；优化器仍是新建，并非中断时的逐批精确恢复。

运行 `python submission2/code/train.py` 才训练；运行 `python submission2/code/predict.py` 才生成 `submission2/submission.csv`。训练前每批正负共现、每轮覆盖所有原始 train 图，少数类可能重复；验证与预测不采样、不随机增强。候选配方同时使用 focal 和 0.1 倍成对排序 AUC 损失，按官方验证 AUROC 严格提高保存。两分支目前每次最多 30/38 轮，早停 8/10 轮；这些是实验设置，尚无实测成绩。本机未启动完整训练，候选目录不含 PTH/CSV，预测前必须先训练并完成选模。

最终如采用候选，需补齐 `submission2/model/`、`pretrain_model/`、核验工作簿和新 CSV，并按规程逐项校验后再整理成正式提交目录；现在不要提交不完整的实验目录。正式版 `submission/` 的旧说明和结果见下文，它不代表新候选。

CSV 命名注意：官方 `test.csv` 的图片名后缀是小写 `.jpg`，磁盘原图后缀却是大写 `.JPG`。`predict.py` 调用的 `write_submission` 现会在写入 `Image_name` 时仅规范后缀为小写，保持原顺序和概率不变；输出文件后缀也统一为小写 `.csv`。已核对全部 5,855 行名称匹配官方 `test.csv`。此修改只影响以后生成的 CSV；当前仓库的历史 `submission.csv` 未改，阶段性模型仍须完成训练与选模后才能预测。

设备与轮次：点击 `submission/code/train.py` 运行时会先打印当前使用 GPU 还是 CPU、PyTorch 与 CUDA 版本。有 CUDA 则优先 GPU；无 CUDA 也可用 CPU，但完整训练可能非常慢。当前本地 `deepStudy` 为 CPU 版。两个模型的 `CONFIG[...]["epochs"]` 当前均为 1，意思是**本次运行各训练 1 轮**；再次点击运行仍从本次第 1 轮开始计数，不需把轮数加到历史累计值。已有最佳权重会先经完整官方验证集复核，之后用于继续优化；只有 AUROC 严格超过上次最佳才替换权重。新保存的 PTH 不再记录历史轮次，仍保留最佳 AUROC 和必要的配方、来源信息。本次代码修改没有启动完整训练，也没有改动已有 PTH 或 CSV。

当前唯一代码目录是 `submission/`，由原 `submission2/` 改名；`glaucoma_first/` 数据目录与之同级。旧 ResNet-18 + DenseNet-121 方案已从当前工作树移除，可从 Git 历史恢复。根层 `submission/submission.csv` 仍是旧方案的 5,855 行历史提交结果，与 `Downloads/submission (4).csv` 字节一致，**不是现用预训练双模型的预测输出**。

现用方案位于 `submission/`：安装适合本机的 PyTorch 和 `submission/code/requirements.txt`，运行 `python submission/code/train.py`。只使用主办方 `glaucoma_first/train` 更新参数、`valid` 选 AUROC。本机已从 Git LFS 取回约 200.8 MB 的真实阶段性 `best_model.pth` 并安全读取：旧文件中 ConvNeXt-Tiny 记录最佳第 6 轮（AUROC 0.984011），EfficientNetV2-S 记录最佳第 3 轮（AUROC 0.965275）；检查点的 `training_complete=False`、`selection=None`，**不能直接预测**。训练机若仅拉到约 134 字节的 LFS 指针，须先运行 `git lfs pull` 取得真实权重。重新运行 `train.py` 会先用完整官方验证集复核已有参数，再从本次第 1 轮训练；旧 PTH 不含优化器状态，故不是精确批次恢复。训练与验证每 25 批打印本批阳性、报阳、报对、误报和漏报。训练完整结束并选好方案后，单独运行 `python submission/code/predict.py` 才写该模型的 CSV。`cost.py` 与 `predict.py` 共用推理函数。0.99 只是检验目标，不能报告为成绩。
